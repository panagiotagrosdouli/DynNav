## 1. Why this file exists

This is the evidence-bound worklog for Contribution 01. It records what the
repository actually implemented, what was executed on GitHub Actions, which
results are negative, and exactly what is missing before any physical-robot
statement can be made. The main [C01 README](README.md) covers the mathematical
research question and historical synthetic experiments. This file focuses on
the newer real-data and robot-hardware evaluation requirements.

**A real map is not a real robot trial.** Recorded LILocBench observations were
captured by a physical Clearpath Dingo, but the alternative C01 A* paths were
computed offline afterward. DynNav C01 did not control that robot.

## 3. Completed work: the real LILocBench occupancy-map pilot

Official source: https://www.ipb.uni-bonn.de/html/projects/localization_benchmark/

Retained CI workflow (successful): https://github.com/panagiotagrosdouli/DynNav/actions/runs/42681341639

Research PR (historical): https://github.com/panagiotagrosdouli/DynNav/pull/215

The official occupancy map was acquired from the university dataset site, its
SHA-256 digests were recorded, and it was ingested through
`dynnav.mapping.ros_map.load_ros_map`.

**Map metadata observed in the run:**

- Image dimensions: **1000 × 1000 cells**.
- Resolution: **0.05 m/cell**.
- Origin: **(-25 m, -25 m, 0 rad)**.
- Blocked and unknown-as-blocked cells: **894,999**.
- Distinct connected free-space components: **243**.
- Map image SHA-256:
  `8a9ff6aa0d954e7743ed7dd1801d9df2a44a4d023cfda8de6ef12daa39cd57bf`.
- ROS YAML SHA-256:
  `6e61ed85520c2e4638684734c738daf63c17de830a535cd8458cee14cd1fb11e`.
- Model SHA-256:
  `640ec68fcf1a04b3fc3abbc146ff5aaaee58a5a170ec5770c39459cce972b19a`.

The CI confirmed the saved neural checkpoint was actually loaded
(`neural_model_loaded: true`), with no silent Manhattan fallback. It produced
five paired start/goal queries generated in connected free map regions.

### Observed pilot results (5 paired queries)

| Algorithm | Mean expanded nodes | Mean path cost, cells | Mean query time, ms |
|---|---:|---:|---:|
| Manhattan A* | **12,648.8** | 286.2 | **59.190** |
| Dijkstra | 33,726.0 | 286.2 | 154.725 |
| Learned raw A* | 14,740.8 | 286.2 | 975.738 |
| Learned Manhattan-clipped A* | 15,082.2 | 286.2 | 1,010.293 |

**Scientific interpretation:** on these five real-map queries, raw learned A*
expanded **16.5% more** nodes and was approximately **16.5× slower** than
classical Manhattan A*. This is a negative learned-efficiency result for the
pilot. All observed paths had equal cost. That empirical equality does not prove
admissibility of the raw network on arbitrary maps. The tiny sample is not
generalization evidence and the runner-specific timings do not establish
robot-wide real-time performance.

The path queries were *generated by the experiment*, not recorded robot
navigation commands; no alternative planner was run onboard the source Dingo.

## 4. What is NOT yet demonstrated

- No physical robot operating the **C01 learned heuristic**.
- No measured real robot `/cmd_vel`, `/odom`, `/tf`, `/scan` and localization
  trace associated with a C01-controlled run.
- No C01-vs-Manhattan matched physical trials with randomized planner order.
- No frozen physical start/goal pairs, map calibration or safety acceptance
  record for the C01 experiment.
- No closed-loop navigation outcome, collision/clearance, emergency-stop,
  replanning, controller behavior, or energy measurements from C01.
- No demonstrated improvement in physical-robot safety or runtime.
- No evidence that this exploratory C01 result validates the paper's C00
  executed-action-dependent return-connectivity claim.

**Consequently `PHYSICAL_ROBOT_VALIDATED = false`. No physically measured C01
performance table is permitted until traceable hardware trials exist.**

## 5. How to reproduce the existing offline real-map pilot

Install the repository's development environment and use an official extracted
LILocBench ROS map YAML with its image.

```bash
python -m pip install -e ".[dev]"
python -m pytest -q contributions/01_learned_astar/tests/test_real_ros_map_eval.py

python contributions/01_learned_astar/experiments/eval_real_ros_map.py \
  /absolute/path/map_office.yaml \
  --model contributions/01_learned_astar/models/heuristic_net_rich.pt \
  --output-dir results/c01_lilocbench_real_map/neural \
  --n-tasks 5 --seed 17 --min-distance 8
```

**Never** reclassify these outputs as hardware results. Check map/model hashes
and source CI artifact before comparing or reusing numerical summaries.

## 6. Physical-robot validation plan (not yet executed)

Follow [C01 physical-robot protocol](PHYSICAL_ROBOT_PROTOCOL.md), alongside
the repository-wide
[`docs/HARDWARE_VALIDATION_CHECKLIST.md`](../../docs/HARDWARE_VALIDATION_CHECKLIST.md).
The actual model (e.g. TurtleBot3 or Dingo), hardware configuration and ROS
drivers must be identified before commissioning.

A real-robot study must:

1. Have a trained, authorized human operator and a reliable independent
   emergency stop. Do not let a language model run unreviewed motion commands.
2. Verify base, LiDAR, TF/odometry, localization, costmaps, velocity limits,
   map frame, safety monitor, and safe low-speed stop **before** C01 motion.
3. Expose the **actual C01** planner or justified equivalent through a testable
   Nav2 planning interface. Verify the selected planner and checkpoint
   identification in runtime telemetry.
4. Freeze a set of valid physical start/goal tasks and safety acceptance criteria
   *before* outcomes are observed.
5. Compare Manhattan A* vs raw and clipped learned A* under matched robot,
   map, task, controller and environment conditions; retain any failed runs.
6. Record `ros2 bag` sensor/TF/command topics plus planning traces, clocks,
   planner config, model SHA-256, calibration, operator and incident history.
7. Measure both algorithmic expansions/latency and **physical outcomes**:
   navigation success, executed path length, elapsed time, clearance,
   localization faults, emergency stops and reversibility where meaningful.
8. Independently review validity, pairing and all logs before calling a trial
   `PHYSICAL_ROBOT_VALIDATED`.

No other contribution should inherit C01 hardware validation automatically.

## 7. Definition of evidence and publication consistency

| Level | Evidence requirement | Current C01 |
|---|---|---|
| S1 — Synthetic | Executed synthetic maps and recorded metrics | Historical data retained |
| S2 — Real recorded map | Official map, hashes, executed offline queries, results | **Verified pilot** |
| S3 — ROS replay | Actual sensor bag replay and associated C01 results | Not verified |
| S4 — Gazebo closed-loop | Recorded C01-controlled simulated robot execution | Not verified |
| S5 — Physical closed-loop | C01 selected onboard, hardware runs and rosbag verified | **Not verified** |

The manuscript `paper/dynnav_r/main.tex` concerns action-triggered
history-conditioned safe-return planning. The public C01 result is a separate
offline learned-search experiment and must **not** be inserted into the
manuscript abstract, primary 96-scenario result table or Gazebo efficacy claims.
Any future C01 paper needs its own hypothesis, map-independent baselines,
checkpoint training provenance, and controlled evaluation.

## 10. Robot-run evidence validation tool (read-only)

The new `experiments/validate_physical_evidence.py` audits a supplied, operator-created trial manifest against actual evidence-file bytes. It checks required provenance fields, SHA-256 digests, path containment, explicit safety attestation, and trial outcome vocabulary. It cannot prove that the telemetry came from a physical robot or that the selected C01 algorithm controlled motion. It intentionally labels structurally valid records `STRUCTURAL_EVIDENCE_PASS_HUMAN_REVIEW_REQUIRED`, **not** `PHYSICAL_ROBOT_VALIDATED`.

```bash
python -m pytest -q contributions/01_learned_astar/tests/test_validate_physical_evidence.py
python contributions/01_learned_astar/experiments/validate_physical_evidence.py \
  /absolute/path/to/actual_robot_trial/manifest.json \
  --output /absolute/path/to/actual_robot_trial/validation.json
```

The manifest must point to an actual locally retained bag data file and actual C01 planner trace, with hash integrity, task/robot provenance, checkpoint identity, operator safety approval and outcome. The tool is **not a substitute** for ROS bag decoding, synchronized time/TF review, robot identity verification or a human hardware safety gate. No trial evidence was supplied in this review; **zero physical C01 runs are claimed**.
